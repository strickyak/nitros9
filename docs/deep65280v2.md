# deep65280v2 Hardware & System Specification

This document provides both the **User Manual** and the **Technical Manual** for the **deep65280** port of NitrOS-9 Level 2 running on the **deep65280v2** engine of the `gep9` emulator.

> [!NOTE]
> Address ranges in this document use `..` to indicate an **inclusive range** (e.g., `$FFA0..$FFAF` includes both `$FFA0` and `$FFAF`).

---

# Part I: User Manual

## 1. Overview

The `deep65280` machine is a 6809/6309 architecture running **NitrOS-9 Level 2** with:
- **512 KB of physical RAM** organized into 64 blocks of 8 KB each (`$00..$3F`).
- **CoCo 3 compatible MMU** mapping registers at `$FFA0..$FFAF` and task switch register at `$FF91`.
- **Permanent locked trampoline page** at `$FExx` hardwired to physical page `$3F`.
- Memory-mapped I/O devices: `EMUDSK` block storage (`$FF80..$FF86`), `CLOCK_AND_STOP` timer and control (`$FF87`), and `ACIA_M6805` serial console (`$FF88..$FF89`).
- **Direct 64 KB pre-populated boot image** (`deep65280.img`) containing 19 kernel and utility modules across slots 1..7.
- **10 MB RBF virtual disk image** (`deep0.dsk`) containing 83 Level 2 commands and Basic09.


# Part II: Technical Manual

## 1. System Architecture & Memory Organization

### 512 KB Physical RAM
Physical memory consists of 512 KB (65,536 × 8 bytes), partitioned into **64 physical blocks of 8 KB each** numbered `$00..$3F`:
- Blocks `$00..$37` (448 KB): Free user RAM, dynamically allocated to user processes.
- Blocks `$38..$3F` (64 KB): System RAM holding the preloaded kernel, device drivers, system tables, and I/O page.

### 64 KB Logical CPU Address Space
The 6809 CPU operates in an 8-slot, 64 KB logical memory space:

| Slot # | Logical Address Range | Size | Cold Boot Mapping | Usage |
|:---:|:---:|:---:|:---:|:---|
| **0** | `$0000..$1FFF` | 8 KB | Block `$38` | System Direct Page (`$0000..$00FF`), Globals (`$0100..$03FF`), System Process Descriptor, Stack |
| **1** | `$2000..$3FFF` | 8 KB | Block `$39` | Free System RAM (available for `F$SRqMem`) |
| **2** | `$4000..$5FFF` | 8 KB | Block `$3A` | Free System RAM (available for `F$SRqMem`) |
| **3** | `$6000..$7FFF` | 8 KB | Block `$3B` | Free System RAM (available for `F$SRqMem`) |
| **4** | `$8000..$9FFF` | 8 KB | Block `$3C` | Lower free RAM (`$8000..$99DA`), Preloaded commands (`$99DB..$9FFF`: `dir`, `setime`, `date`, `stop`) |
| **5** | `$A000..$BFFF` | 8 KB | Block `$3D` | Preloaded System Modules (`$A256..$BFFF`: `scf`, `sc6850`, `clock`, `term`, `shell_21`, `mfree`, `free`, `procs`, `mdir`) |
| **6** | `$C000..$DFFF` | 8 KB | Block `$3E` | Preloaded Storage Subsystem (`$C04D..$DFFF`: `dd`, `emudsk`, `sysgo`, `rbf`, `ioman` abutting `$E000`) |
| **7** | `$E000..$FFFF` | 8 KB | Block `$3F` | `init` (`$E0C7`), `krnp2` (`$E125..$EDFF` abutting `$EE00`), `krn` (`$EE00..$FEFF`), SWIStack (`$FEDF`), I/O Red Page (`$FF00..$FFEF`), Vectors (`$FFF0..$FFFF`) |

## 2. MMU Registers & Task Switching

The `deep65280v2` engine implements CoCo 3 compatible dynamic address translation registers:

### MMU Mapping Registers (`$FFA0..$FFAF`)
Each 8-bit register controls the physical 8 KB block mapped into an 8 KB CPU address slot:
- **Task 0 Registers (`$FFA0..$FFA7`)**: Control slots 0..7 when Task 0 is active.
- **Task 1 Registers (`$FFA8..$FFAF`)**: Control slots 0..7 when Task 1 is active.

Bits [5:0] select physical blocks `$00..$3F`.

### Task Switch Register (`$FF91`)
Writing to `$FF91` controls the active task:
- Bit 0 = `0`: Task 0 active.
- Bit 0 = `1`: Task 1 active.
- Bits 7..1: Ignored.

### Power-On / Boot Defaults
The emulator boots with MMU mode active and:
- Active task: Task 0 (`$FF91 = 0`).
- `$FFA0..$FFA7` pre-initialized to `$38, $39, $3A, $3B, $3C, $3D, $3E, $3F`.
- `$FFA8..$FFAF` pre-initialized to `$38, $39, $3A, $3B, $3C, $3D, $3E, $3F`.

### Permanent Locked Trampoline Page (`$FExx`)
To ensure that interrupt handlers, system call dispatchers, and register stacks in the constant page are never unmapped when switching tasks:
- Memory accesses to `$FE00..$FEFF` are **always hardwired to physical page `$3F`** regardless of the MMU mapping in Slot 7.
- Vectors at `$FFF0..$FFFF` are likewise permanently mapped to physical page `$3F`.

## 3. Memory-Mapped I/O Devices

The top 256 bytes (`$FF00..$FFFF`) of logical address space form the dedicated I/O "Red Page":

### 1. EMUDSK Virtual Disk Interface (`$FF80..$FF86`)

| Address | Register | Description |
|---|---|---|
| `$FF80` | `LSN[23:16]` | High byte of 24-bit Logical Sector Number |
| `$FF81` | `LSN[15:8]`  | Mid byte of 24-bit Logical Sector Number |
| `$FF82` | `LSN[7:0]`   | Low byte of 24-bit Logical Sector Number |
| `$FF83` | `COMMAND` / `STATUS` | Write: `0` = Read Sector, `1` = Write Sector. Read: Status code (`0` = OK, `2` = Not ready, `6` = Seek error) |
| `$FF84..$FF85` | `BUFFER` | 16-bit RAM buffer pointer (big-endian) |
| `$FF86` | `DRIVE` | Drive unit index (`0` = Drive 0 / `deep0.dsk`) |

The virtual disk controller transfers 256 bytes per sector. In `deep65280v2`, target buffer addresses are translated through the active task's MMU mapping registers, and `$FExx` addresses are mapped directly to physical block `$3F`.

### 2. CLOCK_AND_STOP Timer & Control (`$FF87`)

| Address | Register | Description |
|---|---|---|
| `$FF87` | `CLOCK_AND_STOP` | Periodic tick interrupt control, frequency selection, and emulator lifecycle control. |

#### Register Bit Layout (`$FF87`)
- **Bit 0 (`TICK`)**: Firing condition. Read: `1` if clock has ticked. Write: write-1-to-clear (W1C).
- **Bit 1 (`IRQ_EN`)**: IRQ enable (`1` = assert CPU `IRQ` line on tick; `0` = mask).
- **Bits 3..2**: User general-purpose read/write bits.
- **Bits 5..4 (`RATE`)**: Frequency select:
  - `%00` = 60 Hz (~33,333 cycles at 2 MHz)
  - `%01` = 50 Hz (~40,000 cycles at 2 MHz)
  - `%10` = 6 Hz (~333,333 cycles at 2 MHz)
  - `%11` = 0.1 Hz (~20,000,000 cycles at 2 MHz)
- **Bits 7..6**: User general-purpose read/write bits.

#### Abrupt Stop Commands
Writing special command codes to `$FF87` halts the simulator immediately:
- **`$FC`**: Prints message and exits with status 0 (`exit(0)`). Used by the `stop` command.
- **`$FD`**: Prints message and exits with status 1 (`exit(1)`). Used by `PicoCrash`.
- **`$FE`**: Induces an immediate crash/abort.

### 3. ACIA_M6805 Serial Console (`$FF88..$FF89`)

| Address | Register | Description |
|---|---|---|
| `$FF88` | `STATUS` / `CONTROL` | Read: Status register (bit 0 = Rx ready, bit 1 = Tx empty). Write: Control register (write `$03` for master reset). |
| `$FF89` | `DATA` | Read: Received character. Write: Transmit character to emulator console. |

### 4. System Vectors (`$FFF0..$FFFF`)

| Address Range | Vector | Handler in Kernel |
|---|---|---|
| `$FFF2..$FFF3` | SWI3 | Trampoline branch to `SWI3VCT` (`$FEEE`) |
| `$FFF4..$FFF5` | SWI2 | Trampoline branch to `SWI2VCT` (`$FEF1`) |
| `$FFF6..$FFF7` | FIRQ | Trampoline branch to `FIRQVCT` (`$FEF4`) |
| `$FFF8..$FFF9` | IRQ  | Trampoline branch to `IRQVCT` (`$FEF7`) |
| `$FFFA..$FFFB` | SWI  | Trampoline branch to `SWIVCT` (`$FEFA`) |
| `$FFFC..$FFFD` | NMI  | Trampoline branch to `NMIVCT` (`$FEFD`) |
| `$FFFE..$FFFF` | RESET | Direct entry to `entry` in `krn` (`$F058`) |

## 5. Kernel Modifications for `deep65280`

To adapt the NitrOS-9 Level 2 kernel to the `deep65280` architecture, specific targeted modifications were made under the `deep65280` build condition:

### 1. [`defs/deep65280.d`](file:///home/strick/modoc/coco-shelf/nitros9/defs/deep65280.d)
- Configured Level 2 equates: `Level set 2`, `SysBlock equ $38`, `KrnBlk set $3F`.
- Set `Bt.Start set $2000`.
- Defined MMU registers (`DAT.Regs equ $FFA0`, `DAT.Task equ $FF91`).
- Defined hardware addresses for `EMUDSK`, `CLOCK_AND_STOP`, and `ACIA`.

### 2. [`level2/modules/kernel/krn.asm`](file:///home/strick/modoc/coco-shelf/nitros9/level2/modules/kernel/krn.asm)
- **Zero Page & DP Setup**: Enabled clearing of page 0/1 (`$0000..$1FFF`) at cold start under `IFNE picothing+deep65280`.
- **System DAT Image**: Initialized `P$DATImg` in the system process descriptor to physical blocks `$0038..$003F` across slots 0..7.
- **Physical Block Map (`D.BlkMap`)**:
  - Configured 64 blocks (`$00..$3F`) with block map bounds `$0200..$0240`.
  - Blocks `$00..$37` left as `0` (free RAM).
  - Blocks `$38..$3F` marked as `RAMinUse` ($01).
- **System Page Map (`D.SysMem`)**:
  - Pages `$20..$98` marked `0` (free system pages, 121 pages / ~31 KB for `F$SRqMem`, keeping dynamic descriptors strictly below the `$A000..$DFFF` copy window).
  - Pages `$99..$FE` marked `RAMinUse` (preloaded modules, Kernel, and SWIStack).
  - Page `$FF` marked `NotRAM` (I/O Red Page).
- **Module Validation**:
  - Validates preloaded modules across slots 1 through 7 (`$2000..$FDFF`) using `I.VBlock`.
  - Bypasses CoCo memory probe and legacy `KrnSystemMemoryMap` routine so `D.SysMem` free pages are preserved.
- **Crash Handler**:
  - `PicoCrash` writes `$FD` to `CLOCK_AND_STOP` (`$FF87`), causing `gep9` to exit cleanly on fatal kernel crash.

### 3. [`level1/modules/kernel/fsrqmem.asm`](file:///home/strick/modoc/coco-shelf/nitros9/level1/modules/kernel/fsrqmem.asm)
- Configured `F$SRqMem` to begin searching for free system pages from the top of the map downward (`leay 256,x`) under `IFNE wildbits+deep65280`.
- Disabled secondary bootstrap `FBoot` with an immediate `rts` under `IFNE wildbits+deep65280`.

### 4. [`level2/modules/kernel/fld.asm`](file:///home/strick/modoc/coco-shelf/nitros9/level2/modules/kernel/fld.asm) & [`fldabx.asm`](file:///home/strick/modoc/coco-shelf/nitros9/level2/modules/kernel/fldabx.asm)
- In cross-task memory transfer routines (`F$Move`, `F$LDABX`, `F$STABX`), when restoring the Slot 0 mapping, loads `#SysBlock` (`$38`) into `DAT.Regs` instead of assuming physical block 0 (`$00`).

### 5. [`level1/modules/sysgo.asm`](file:///home/strick/modoc/coco-shelf/nitros9/level1/modules/sysgo.asm)
- Excluded CoCo-specific hardware checks (BASIC warm-reset vector, Shift-key sensing) from `SysGo` under `deep65280`.
